작업을 마무리합니다. 다음 검증 흐름을 순서대로 실행하세요.

## 실행 흐름

### Step 1 — REFLECT (변경 범위 검증)
1. 이번 작업에서 수정한 파일 목록을 정리한다
2. 각 파일이 원래 작업 범위 안에 있는지 확인한다
3. 의도하지 않은 변경(스타일값, 무관한 컴포넌트)이 있으면 되돌린다

### Step 2 — 품질 게이트

아래 명령을 순서대로 실행한다. 코드를 읽고 추론하지 않는다.

**Gate 1 — TypeScript**
```bash
npx tsc --noEmit
```
에러 있으면 FAIL. 수정 후 재실행.

**Gate 2 — ESLint**
```bash
npm run lint
```
에러 있으면 FAIL (워닝은 허용).

Gate 3(상태 관리 경계), Gate 4(변경 범위)는 Step 1에서 이미 확인됨.

결과를 출력한다:

```
🔍 품질 게이트 검사
─────────────────
Gate 1 타입 안전성  ✅ / ❌
Gate 2 코드 품질    ✅ / ❌
Gate 3 상태 경계    ✅ / ❌  (Step 1 검증 결과)
Gate 4 변경 범위    ✅ / ❌  (Step 1 검증 결과)

결과: PASS ✅ / FAIL ❌
─────────────────
```

FAIL 항목이 있으면 수정 후 재확인. 커밋 불가.

### Step 3 — 계획 파일 완료 마커 추가

`.claude/plans/` 에 활성 계획 파일이 있으면 파일 끝에 아래를 추가한다:

```markdown
## Status: done
```

이 마커가 있으면 scope-guard가 해당 계획을 비활성으로 인식하여 이후 파일 수정을 차단하지 않는다.

### Step 4 — 커밋 메시지 생성
게이트 통과 후 커밋 메시지를 제안한다:

```
feat|fix|refactor|style|test|chore: [작업 요약]

- [변경 내용 1]
- [변경 내용 2]
- ...

Co-Authored-By: Claude Sonnet 4.6 <noreply@anthropic.com>
```

### Step 5 — 세션 로그 기록

`.claude/logs/` 디렉토리에 `YYYY-MM-DD-HH-MM.md` 형식으로 세션 로그를 저장한다.
디렉토리가 없으면 생성한다.

```markdown
## 세션 로그
- 날짜: [YYYY-MM-DD HH:MM]
- 작업 요약: [1-2줄]
- 수정 파일 수: [git diff --stat 기준]

### 컨텍스트 소비 분석
- 가장 큰 비용: [예: 22파일 병렬 Read, scope-guard 재시도 등]
- 불필요했던 작업: [예: 계획 파일 누락으로 Edit 22회 거부→재시도]
- 효율적이었던 패턴: [예: 병렬 grep으로 한 번에 파악]

### 다음 세션 개선 포인트
- [구체적 액션. 예: "계획 파일에 파일명을 미리 전부 기재"]

### 계획 준수도
- 계획대로 진행됨 / 벗어남 (사유: ...)
```

### Step 6 — 최종 요약 출력

```
✅ /done 완료 (자기 검증)
─────────────────
수정 파일 수: N개
품질 게이트: PASS
세션 로그: .claude/logs/YYYY-MM-DD-HH-MM.md

⚠️  다음 단계:
  MEDIUM/HIGH 복잡도 → 새 세션에서 git diff 기준으로 독립 검토 권장
  이유: 구현 대화가 쌓인 세션에서는 자기 검증 편향이 생깁니다.
─────────────────
```

커밋은 사용자 확인 후 실행한다. 자동으로 커밋하지 않는다.
