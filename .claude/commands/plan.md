구현 계획을 작성하고 파일로 저장합니다. 코드에 손대기 전에 실행하는 커맨드입니다.

## 입력
`$ARGUMENTS` 형식: `[티켓번호 또는 작업설명]`

---

## 실행 흐름

### Step 1 — 의도 확인
`$ARGUMENTS`를 보고 작업 의도가 불명확하면 먼저 묻는다.
명확하면 바로 Step 2로.

아래 질문을 사용자에게 던진다 (해당되는 것만):
- 어떤 상태관리 방식을 선호하는가? (기존 패턴 따를지, 새 패턴 쓸지)
- UI가 있다면 컴포넌트를 어떻게 나눌 것인가?
- 기존 코드를 수정할지, 새로 만들지?
- 테스트 범위는 어디까지인가?

### Step 2 — 코드 탐색
변경이 필요한 파일과 연관 파일을 읽는다.
탐색 결과를 바탕으로 현재 코드 구조를 파악한다.

### Step 3 — 계획 초안 작성
아래 형식으로 계획 초안을 작성한다:

```
## 구현 계획: [작업 제목]
작성일: [날짜]
티켓: [번호 / 없으면 "-"]
복잡도: LOW / MEDIUM / HIGH

### 목표
[무엇을 만들고 왜 만드는지 1-3줄]

### 현재 상태
[현재 코드가 어떻게 되어 있는지 요약]

### 구현 전략
[어떤 접근 방식을 택할지, 왜 그 방식인지]

### 구현 순서
1. [파일명] — [할 일]
2. [파일명] — [할 일]
...

### 상태관리 결정
- 서버 상태: [TanStack Query / 해당 없음]
- 전역 UI 상태: [Jotai / 해당 없음]
- 폼 상태: [RHF / 해당 없음]

### 정책 키워드
- 포함 여부: YES / NO
- 해당 항목: [날짜계산 / 금액 / 권한 / 상태값]
- 테스트 필요: YES / NO

### 리스크
- [예상 리스크 또는 "없음"]

### 완료 기준
- [ ] [확인 항목 1]
- [ ] [확인 항목 2]
```

### Step 4 — 사용자 확인
계획 초안을 보여주고 묻는다:

```
이 계획대로 진행할까요?
[Y] 진행 / [N] 취소 / [E] 수정
```

수정 요청이 오면 반영 후 다시 확인.

### Step 5 — 파일로 저장
승인되면 `.claude/plans/[날짜]-[티켓번호 또는 작업요약].md` 로 저장한다.

예시 파일명:
- `.claude/plans/2026-04-08-TIMF-42-order-status-column.md`
- `.claude/plans/2026-04-08-refactor-payment-table.md`

저장 후 출력:
```
계획이 저장됐습니다: .claude/plans/[파일명]
구현을 시작하세요. (/done 으로 완료 검증)
```
